#Matrix Dropbox Bot

**Matrix Dropbox** — асинхронный бот для Matrix-сервера, который принимает файлы (изображения и документы) от пользователей и распределяет их по папкам на SMB-шарах. Бот поддерживает два режима работы:
**Общий Dropbox** — комната, куда приглашаются все пользователи. Файлы распределяются по общему списку папок из folders.json.
**Личный Dropbox** — персональная комната для каждого пользователя из whitelist (drop_users.json). К общему списку папок добавляется пункт "Личная папка" (*), позволяющий сохранять файлы в свою персональную папку на smb-шаре.Каждая личная папка автоматически дополняется подпапкой MATRIX_DROPBOX, в которой бот хранит файлы и автоматически удаляет файлы старше 2 недель.

##Защита от ошибок и конфликтов
```
| Проблема | Решение |
| ------ | ------ |
|  Повторная обработка старых событий |Фильтр по origin_server_ts (события старше 60 сек) + сохранение sync_token |
|  Перезапись файлов при нескольких запросах |Очередь в Redis (FIFO) — каждый файл обрабатывается последовательно	 |
| 	Потеря файлов при падении бота	 | 	Фоновая задача orphan_cleanup_loop удаляет временные файлы без состояния в Redis	 |
| 	Конфликт имён файлов	 | 	При совпадении добавляется timestamp: photo_20261002_153045.jpg	 |
| 	Недоступность SMB-сервера	 | 	Таймаут 30 секунд + автоматическое переподключение	 |
| 	Зависание при загрузке	 | 	asyncio.wait_for(..., timeout=30.0) в upload_file	 |
| 	Разные SMB-серверы	 | 	SMBClient регистрирует сессии для каждого сервера отдельно	 |
| 	Нежелательные комнаты	 | 	Whitelist ROOM_ID + ROOM_ID_PRIV; приватные комнаты только по приглашениям из whitelist	 |
| 	Неавторизованные команды	 | 	Проверка ADMIN_USERS перед выполнением админских команд	 |
| 	Бот реагирует на свои сообщения	 | 	Фильтр event.sender == client.user_id	 |
| 	Конфликт типов Redis-ключей	 | 	Отдельные ключи для очередей (List), файлов (String), состояний (String)	 |
| 	Параллельные запросы !drop	 | 	Lua-скрипт атомарной привязки + Redis-блокировка SET NX EX 30	 |
```
##Автоочистка старых файлов
```
Фоновая задача old_files_cleanup_loop каждый час проходит по всем пользователям из whitelist и удаляет файлы старше 14 дней только в личных папках MATRIX_DROPBOX.
Важно: папки из folders.json НЕ затрагиваются — они могут содержать важные долгосрочные данные.
```
```
# Логика очистки:
for user_id, drop_user in drop_manager.users.items():
    server, share, rel_path = _parse_smb_path(drop_user.smb_path)
    deleted = await smb_client.delete_old_files(server, share, rel_path, 14)
```    
  
##Безопасность
```
Комнаты
-Приватность: visibility="private" — комната не попадает в публичный каталог.
-Доступ: join_rules="invite" — войти можно только по приглашению.
-Федерация: m.federate=False — комната не реплицируется на внешние сервера.
-Права: бот имеет PL=100 (полный контроль), пользователь PL=0 (только писать/загружать).
Команды
-Админские команды (!list, !drop_users, !drop_create, !drop_reset, !drop_reload, !reload) проверяют ADMIN_USERS.
-Пользовательские команды (!drop, !drop_status, !cancel) доступны всем.
Файлы конфигурации
-Секреты хранятся в .env (исключён из Git через .gitignore).
-Runtime-файлы (drop_users.json, personal_rooms.json, folders.json) монтируются через volume.
```
